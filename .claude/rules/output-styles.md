# Output styles

Loaded on demand when you touch `.claude/output-styles/`. Relocated verbatim
from the root `CLAUDE.md`; the `keep-coding-instructions` requirement also stays
inline there, because a brand-new style file is *written* rather than read, and a
`paths:` rule only fires on a read.

- `.claude/output-styles/` — opt-in reply formats (one `.md` per style, YAML frontmatter with `name`/`description`, and `keep-coding-instructions: true` so a style never touches coding behaviour). Ships `brief.md` ("Brief"), which `settings.json` sets as the **default** `outputStyle` — a deliberate owner decision (this repo exists to ship opinionated defaults), made viable by the fact that `{"outputStyle": "Default"}` in `settings.local.json` restores the stock voice without forking the baseline. `Default` is a real built-in style name; don't "turn it off" by inventing a value or removing the key from the tracked file. Always set `keep-coding-instructions: true` — the field defaults to `false`, which silently drops Claude Code's built-in engineering instructions. Styles apply to the **main conversation only** (a fork is the exception, inheriting the parent's prompt); subagents run their own prompt, which is what keeps chat formatting out of PR bodies. Needs a matching `!.claude/output-styles/` line in the root `.gitignore` and an entry in `install.sh`'s `FALLBACK_DEFAULTS`, same as `scripts/`. Credit for borrowed ideas belongs in the READMEs, not in the style body — the body is re-sent every session. **Why `Brief` survives the built-in `Concise` style** (added v2.1.237): `Concise` covers only leading with the result, skipping preamble, and staying short by default. It says nothing about the `Needs you:` queue of executable numbered steps, numbering multi-item output so a reader can answer "re: 2", the ban on stating cost or token spend in prose (load-bearing — the status line is the only place those numbers are real), or the marker discipline whose verb glyphs `AWAITING.md` and `show-awaiting.sh` depend on literally. Four load-bearing behaviours, so `Brief` stays — but the audit ran both ways: `Concise` guarantees that error reports, security warnings and destructive-action confirmations are never shortened, `Brief` did not, and that rule has been adopted. **Scope of that comparison, stated honestly: it was made against `Concise`'s documented behaviour, not by running it.** A built-in style's body is not readable from the repo, so a behavioural A/B needs someone to actually switch and use both. The documented differences are enough to justify keeping `Brief`, and the marker discipline is independently load-bearing because `show-awaiting.sh` greps for those glyphs — but if the two are ever compared in use and `Concise` turns out to cover more than its description says, this decision is worth revisiting.
